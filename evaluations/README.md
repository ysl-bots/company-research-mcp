# KOSPI 상위 30개사 DART 평가

인터뷰에서 모집단 기준일과 대상 공시를 정하면 접수번호별 원문을 수집한다.

    uv run python -m evaluations.capture 접수번호

DART_API_KEY는 환경변수로 전달한다. 두 평가 단계는 같은 접수번호와 SHA-256으로 식별한 ZIP을 읽는다. 원문은 data/에 로컬 보관한다.

## 인터뷰용 평가 설계 초안

1. 기업과 공시별로 수집 계획 버전, 원문 위치, 실제 수집 산출물, MCP 요청과 응답을 연결한다.
2. 정적 검사에서 계획의 필수 항목, 수집 코드의 항목 매핑, 산출물의 존재와 원문 일치를 확인한다.
3. Judge는 같은 사례의 원문 구절을 인용해 의미상 누락과 왜곡을 판정한다. 원문에 있고 계획에 없는 내용은 합의한 요구사항이 있을 때만 계획 결함으로 분류한다. 수집 산출물이 정상이면 MCP 응답 생성 경로를 별도로 확인한다. 증거가 부족하면 원인 미확정으로 기록한다.

사례 데이터와 채점기를 분리하는 구조는 [OpenAI Evals](https://github.com/openai/evals)를 참고했다. Judge의 장문 선호 편향과 사람 판정과의 일치도를 검토하는 근거는 [Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)다. 도구 범위, 정적 검사 규칙, Judge 모델, 루브릭과 사람 검수 표본은 인터뷰에서 확정한다.

## 1차 평가 범위

2026-11-26 종가 기준 KOSPI 보통주 시가총액 상위 30개사를 대상으로 한다. 우선주 시가총액은 합산하지 않는다. 기준일 현재 공개된 기업별 최신 사업보고서 1건과 해당 사업연도의 get_dart_filings 응답을 비교한다. 순위 원자료, 종목코드, DART 고유번호, 접수번호를 고정한 뒤 원문을 받는다.

## 합의한 공통 필수 항목

1. 주력 사업·제품과 부문별 매출 구성
2. 시장 여건과 경쟁 요소
3. 연구개발과 투자 방향
4. 최근 3개년 매출과 영업이익

각 항목은 해당 기업이 공시한 범위에서 평가한다. 원문 표·문단을 식별하고 수치의 기간·단위·연결 또는 별도 기준을 보존한다. 미공시와 수집 누락은 구분한다. 부채비율과 영업활동 현금흐름은 선택 항목이며 공통 필수 충족률에서 제외한다.

## 합의한 취업 활용성 기준

- 기업 고유성. 응답에서 뽑은 핵심 소재에 기업명만 바꿔 넣어도 설명이 성립하는지 검토한다. 제품명이나 고유명사의 등장만으로 판단하지 않고, 어떤 사업·기술·시장 여건이 그 회사에 중요한지 원문 근거를 확인한다.
- 개인 경험과의 접점. 동일한 기업 근거에 지원자의 경험을 함께 제공했을 때, 경험에서 실제로 한 일과 기업의 구체적 과제 사이에서 가장 적합한 접점을 골라 설명하는지 평가한다. 판정 근거는 기업 원문과 경험 입력 양쪽에서 찾는다.

MCP는 근거를 반환하고 호스트 모델이 활용 답변을 작성한다. 동일 기업·경험·질문·호스트 모델을 고정한 쌍으로 답변을 생성한다. 한 답변에는 get_dart_filings 응답의 근거를, 다른 답변에는 같은 접수번호의 DART 원문에서 독립적으로 확인한 근거를 제공한다. 두 답변 모두 기업 고유성과 경험 접점을 평가한다. 점수 차이만으로 원인을 확정하지 않고 실제 제공된 근거와 답변을 대조한다.

경험 사례는 공통 비교용 가상 경험과 실제 활용성 확인용 익명화 경험을 함께 사용한다. 사례마다 지원자가 수행한 행동과 판단, 결과를 기록하며 동일 쌍에는 같은 경험 입력을 사용한다. 직무 구성과 사례 수, 원문 근거 선정 절차는 인터뷰에서 확정한다.
